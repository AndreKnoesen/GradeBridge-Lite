# Step 0 baseline — the 16 captures, before the quality gate

**2026-09-01. Student Submission app, branch `handwritten-stage2a`.**
Step 0 of `GradeBridge2026/workorders/WORKORDER_QUALITY_GATE_2026-09-01.md`.

This is the honest starting point the work order asks for, taken **before** any
gate code exists. Nothing was fixed, tuned or rescued to produce it. The three
disagreements with `LABELS.csv` and the three captures over the 2 s budget are
recorded as measurements, not as problems already being worked on.

---

## What changed

One line, `services/markDetect.ts:97`:

```diff
-export const LOCAL_RADIUS_MARKS = 3.0;
+export const LOCAL_RADIUS_MARKS = 2.5;
```

Work order step 0.2. The radius had been moved to 3.0 without a measurement and
is the suspected cause of the cap03 regression. It is the binarizer's local-mean
radius as a multiple of the mark's own side, consumed at `markDetect.ts:141` via
`adaptiveInk`, and it is read by `tests/inkProbe.mjs`. Uncommitted at the time of
writing; tree was otherwise clean at `1b806af`.

Guard rail 5 says a constant may not move without all 16 re-run and the table
reported. That is what the rest of this document is. There is no "before" column
because 3.0 is the value being reverted, not a candidate being compared.

## How it was measured

Every capture goes through the app's own ingest before registration ever sees it
— `ingestLikeApp` in `tests/realCaptures.mjs`, which mirrors
`imageIngest.ingestPage`: EXIF orientation applied, stepped down in halves to
2200 px on the long edge, re-encoded at JPEG q85, decoded back. Measuring the
4032 x 3024 original would be measuring an image the app never processes.

Then a single `registration.registerPage(img)` per capture, timed around that
call alone. Node v22.17.0, Windows. Sources loaded through `loadModule`, so the
TypeScript under test is the app's, not a copy.

The probe is reproduced in the appendix. It was run from the scratchpad and
nothing was added to `tests/`.

Two runs. **Verdicts, statuses, mark counts and residuals were identical in
both**; the milliseconds below are the second run's.

## What the numbers say, and only that

- **11 usable, 5 rejected. 13 of 16 agree with the `review` column.**
- **No throws.** Every one of the 16 returned a verdict.
- **Residual is under 1.0 mm on all 11 that register.** Worst is cap06 at
  0.983 mm; the other ten are at or under 0.9 mm.
- **Three captures exceed the 2 s budget**: cap04 2992 ms, cap08 3512 ms,
  cap09 3586 ms. The other thirteen are 534–1057 ms.
- **The three disagreements with `LABELS.csv`:**
  - **cap03** — labelled FAIL, rejected. It agrees on the verdict but not on the
    ground: the rejection is a 251 mm residual, not the missing fourth mark. The
    detector reported 4 candidates on a photograph the label says physically
    contains three.
  - **cap04** — labelled PASS, rejected at 336 mm. This is the false reject the
    work order attributes to two other printed sheets in frame carrying their
    own correctly printed corner marks.
  - **stale05** — labelled PASS ("tilt is not a defect"), rejected as
    `too_few_marks`.
- **cap09 differs from the work order's account of it.** The work order records
  the decoder *succeeding and returning an empty string*, which is its clearest
  argument for the sharpness check. At this ingest scale the decode fails
  outright (`no_qr`, QR FAIL). The failure is the safe one; the empty-string
  behaviour was presumably observed at a different scale or on the original.

None of the above has been acted on. No detector constant other than
`LOCAL_RADIUS_MARKS` was touched, no threshold was set, and no gate was built.

## Appendix — the probe

```js
// Baseline over all 16 captures (real/ 11 + stale/ 5). Read-only.
import { webcrypto } from 'node:crypto';
globalThis.crypto ??= webcrypto;

import { readdirSync, existsSync } from 'node:fs';
import { join } from 'node:path';

const TESTS = '<abs path>/GradeBridge-Student-Submission/tests';
const { loadModule, CAPTURE_DIR } = await import(`file:///${TESTS}/captureSet.mjs`);
const { ingestLikeApp } = await import(`file:///${TESTS}/realCaptures.mjs`);

const reg = await loadModule('services/registration.ts', 'r_base.mjs');

const dirs = [join(CAPTURE_DIR, 'real'), join(CAPTURE_DIR, 'stale')];
const files = [];
for (const d of dirs) {
  if (!existsSync(d)) continue;
  for (const n of readdirSync(d).filter(n => /\.(jpe?g|png)$/i.test(n)).sort()) {
    files.push({ name: n.replace(/\.[^.]+$/, ''), path: join(d, n) });
  }
}

for (const f of files) {
  const img = ingestLikeApp(f.path);
  const t0 = Date.now();
  let r = null, err = null;
  try { r = reg.registerPage(img); } catch (e) { err = e; }
  const ms = Date.now() - t0;
  // name, usable/status, marksFound, qr, residualMm, ms
}
```

`tests/realProbe.mjs` does the same for `real/` alone and prints the manifest
column beside it; this probe exists only because `listRealCaptures()` does not
walk `stale/`.
